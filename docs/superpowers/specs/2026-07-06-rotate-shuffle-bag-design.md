# Rotate 選択アルゴリズム改善: シャッフルバッグ方式

日付: 2026-07-06
ステータス: 設計承認済み

## 背景と課題

現行の `/rotate template use` は重み `1 / (selectionCount + 1)` の重み付き
ランダム抽選(`src/utils/rotateHelpers.ts` の `selectParticipants`)。
2つの課題がある:

1. **連続・偏り** — 確率的な抑制のみのため、同じ人が短期間に何度も
   当たることがある
2. **新メンバー問題** — 途中参加者は count=0 で重み最大となり、既存メンバー
   の count が大きいほど新メンバーばかり選ばれる期間が続く

## 解決方針: シャッフルバッグ

全メンバーをシャッフルした「袋」から順に引き、袋が空になったら再シャッフル
する(トランプの山札方式)。

- 全員に一巡するまで同じ人は再登場しない → 連続偏りが構造的に消える
- 新メンバーは現在の袋の残りにランダム挿入 → 即座に公平
- 一巡内の順序はランダムなので抽選の楽しさは残る
- チームへの説明が一言で済む(納得感)

検討して見送った代替案:

| 案                                                       | 見送り理由                                     |
| -------------------------------------------------------- | ---------------------------------------------- |
| 現行方式の補正(count中央値初期化 + 直前選出者の重み半減) | 確率的にマシになるだけで連続当選は根治しない   |
| SWRR(平滑化重み付きラウンドロビン)                       | 公平だがほぼ決定的になり抽選のドキドキが消える |

## データ構造

`FacilitatorTemplate`(`src/models/facilitatorTemplate.ts`)に1フィールド追加:

```typescript
export interface FacilitatorTemplate {
  // ...既存フィールド...
  selectionCounts: { [name: string]: number }; // 維持(統計用)
  bag: string[]; // 追加: 現在の巡で「まだ引かれていない」名前の順序リスト
}
```

- `StoredFacilitatorTemplate` では `bag?: string[]`(optional)
- `loadTemplates` は `bag ?? []` でデフォルト。空袋は次回使用時に自動
  再シャッフルされるため、**既存テンプレートの移行処理は不要**
- `selectionCounts` は選出のたびに +1 を継続(ロードマップ 2-4 の統計用)

## 抽選アルゴリズム(`/rotate template use` count=N)

```
1. bag から participants に存在しない名前をフィルタで除去
2. bag の先頭から N 人を引く
3. 途中で bag が空になったら:
   a. 全参加者を再シャッフルして新しい袋を作る
   b. 「この呼び出しで既に選出済みの人」はスキップして引く
      (count>1 で巡をまたいでも同一結果内に重複しない)
4. 巡の境界ガード: 再シャッフル時、新袋の先頭が「直前に引かれた人」なら
   ランダムな別位置とスワップ(参加者2人以上のとき)
   → 呼び出しをまたいだ連続当選も構造的に消える
5. 抽選終了時に bag が空なら、その場で再シャッフル(境界ガード込み)して
   から保存する。空袋を永続化しないことで、次回呼び出し時に「直前に
   引かれた人」を覚えておく必要がなくなる(lastDrawn の永続化不要)
6. selectionCounts を選出者ごとに +1
7. 更新後の bag を永続化
```

実装は `src/utils/rotateHelpers.ts` に純粋関数を追加:

```typescript
drawFromBag(
  participants: string[],
  bag: string[],
  count: number,
  rng: () => number = Math.random,
): { selected: string[]; bag: string[] }
```

(直前選出者は同一呼び出し内の選出結果から分かるため、`lastDrawn` 引数は
不要 — 手順5参照。)

`rng` を注入可能にしてテストを決定的にする。

`/rotate run`(アドホック、履歴なし)は現行の一様ランダムのまま変更しない。

## メンバー変更時の袋の扱い

| 操作                            | 袋の挙動                                                                                                                    |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `add-member`                    | 新メンバーを現在の袋の残りにランダム位置で挿入。`selectionCounts` は 0 初期化のまま(選出確率は袋が決めるため偏りは生じない) |
| `remove-member`                 | 袋から該当名を除去(いなければ何もしない)                                                                                    |
| `template save`(既存名の上書き) | 参加者リストの全面再定義なので袋はリセット(新リストを再シャッフル)。巡の仕切り直しは自然な挙動                              |

counts の reconcile は現行 `upsertTemplate` の仕組みを流用し、bag のフィルタ
を追加する。

## エッジケース

| ケース                                                                    | 挙動                                                           |
| ------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 参加者1人                                                                 | 常にその人。境界ガードはスキップ                               |
| count = 参加者数(ヘルパー単体の挙動。コマンド層は count < 参加者数を強制) | 全員選出。袋はその場で再シャッフルされ、満杯の状態で保存される |
| 袋に participants に無い名前(手動編集等)                                  | 抽選前にフィルタで除去                                         |
| 既存テンプレート初回使用(bag なし)                                        | bag=[] → 自動シャッフルで開始                                  |

## テスト方針(TDD)

- `drawFromBag` を rng 注入で決定的にユニットテスト:
  - 一巡で全員が一度ずつ出る
  - 巡境界で直前選出者が新袋の先頭に来ない
  - count>1 の巡またぎで同一結果内に重複しない
  - 新メンバー挿入位置(add-member ヘルパー側)
- ストレージ層: bag の永続化・デフォルト・reconcile を temp ファイルで検証
  (既存パターン踏襲)
- コマンド層: 既存の discord.js モックテストに bag 更新の検証を追加

## ロードマップへの影響

2-4(`/rotate template stats`)の表示内容が変わる:
「重みで次に選ばれやすい順」→「選出回数 + 今の巡でまだ選ばれていない人」。
